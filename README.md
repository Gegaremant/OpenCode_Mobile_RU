# OpenCode Mobile (Русская локализация)

> ## ⚠️ Поддержка прекращена
>
> **Разработка и поддержка этой сборки остановлены.**
>
> **Почему.** opencode перешёл на веб-доступ: в **версии 2** вышел собственный
> нативный веб-интерфейс, который открывается в браузере и работает с тем же
> сервером по тому же API. Он устанавливается на телефон как обычное
> приложение. Когда официальный веб-клиент делает то же самое и обновляется
> вместе с сервером, поддерживать отдельное нативное Android-приложение не
> имеет смысла: оно отстаёт по определению, а набор его отличий (русская
> локализация, голосовой ввод, архив сессий, черновики) не компенсирует
> необходимость вручную портировать клиент на каждое изменение API.
>
> **Что делать вместо этого.** Откройте веб-интерфейс opencode в браузере на
> телефоне и установите его как приложение — в Chrome это «Установить
> приложение» / «Add to Home screen». Он официальный, актуальный и не требует
> ни сборки, ни обновлений с нашей стороны.
>
> **Что будет с уже собранной версией.** Последний APK, **v0.4.15-ru.v2**,
> продолжит работать. Он не зависит от браузера, не требует ничего от нас и
> останется функциональным столько, сколько будет работать серверная часть
> opencode.
>
> **Когда он перестанет работать.** Приложение разговаривает с сервером по
> открытому HTTP API opencode, и этот API меняется без предупреждения. Как
> только разработчики opencode внесут в него несовместимое изменение,
> приложение перестанет подключаться — и починить это здесь нечем: клиент и
> сервер обновляются независимо, а синхронизировать их в одном форке и есть
> та работа, от которой мы отказались. В этот момент правильное решение —
> перейти на веб-интерфейс, а не чинить нативный клиент.
>
> **Что с репозиторием.** Сборка остановлена: автоматический пересбор не
> запускается, новых APK не будет. Сборщик сохранён в
> [`.github/workflows/sync-and-build.yml`](.github/workflows/sync-and-build.yml)
> и запускается вручную из вкладки Actions — он остаётся рабочим, это
> единственное письменное описание того, как был собран релиз. Скрипты
> `backup-session.sh` и `squash-history.sh` продолжают работать, они к
> приложению отношения не имеют.
>
> Что именно было сделано в этом форке и почему — изложено в коммитах истории
> и остаётся справедливым независимо от того, продолжит ли проект жить.

> **Не является официальным продуктом opencode.** OpenCode Mobile — независимый, созданный сообществом клиент, который не разработан, не одобрен и не связан с opencode / Anomaly. Приложение подключается к серверу opencode, который вы запускаете самостоятельно, используя открытый HTTP API opencode.


**Open-source Android-клиент для [opencode](https://github.com/sst/opencode) AI coding agent.**

OpenCode Mobile — приложение на React Native / Expo, которое переносит возможности [opencode](https://github.com/sst/opencode) AI coding agent на ваш телефон. Подключайтесь к своему серверу opencode через локальную сеть, Cloudflare Tunnel, ngrok или Tailscale — и пишите, просматривайте и отправляйте код из любой точки. Мобильный клиент **бесплатный и open-source** по лицензии MIT. Нет ограничений функций, нет телеметрии, которую вы не включали, и нет рекламы.

## Возможности

- **Офлайн демо-режим** — нажмите «Попробовать демо», чтобы увидеть полный пример исправления бага (рассуждение → grep → diff → запрос разрешения) без настройки
- **Множество подключений** — управление несколькими серверами opencode (локальная сеть, Cloudflare Tunnel, ngrok, Tailscale)
- **Биометрическая блокировка** — Face ID, Touch ID или отпечаток пальца для защиты приложения и отдельных отправок сообщений
- **Стриминговый чат** — посимвольная трансляция ответов с вашего сервера opencode
- **Просмотр diff** — наглядное отображение изменений в файлах
- **Подтверждение вызовов инструментов** — просмотр и одобрение (или отклонение) вызовов инструментов перед выполнением
- **Архив сессий** — в архив отдельного чата или сразу всех чатов проекта, отдельный список архива и возврат чата обратно
- **Выгрузка переписки** — поделиться диалогом в Markdown или скопировать его в буфер обмена
- **Голосовой ввод на языке интерфейса** — распознавание следует за языком приложения (ru-RU / en-US)
- **Безопасное хранение учётных данных** — учётные данные сервера хранятся в Android Keystore через `expo-secure-store`
- **Управление сессиями** — просмотр, создание и возобновление сессий программирования

## Быстрый старт

**Ещё нет сервера?** Установите приложение и нажмите **«Попробовать демо»** на экране сессий — настройка не требуется.

**Шаг 1 — Запустите opencode на своём компьютере**

```bash
# Установите opencode (если ещё не установлены)
npm install -g opencode-ai

# Запустите opencode в режиме сервера
OPENCODE_SERVER_PASSWORD=вашпароль opencode serve --hostname 0.0.0.0 --port 4096
```

**Шаг 2 — Установите OpenCode Mobile** через [прямой APK](#установка-android).

**Шаг 3 — Добавьте подключение в приложении**

Откройте приложение, нажмите **«Добавить подключение»** и выберите тип:

- **Локальная сеть** — LAN IP вашего компьютера, например `http://192.168.1.100:4096`
- **Туннель** — URL Cloudflare Tunnel или ngrok, например `https://my-opencode.trycloudflare.com`
- **Tailscale** — Tailscale IP вашего компьютера, например `http://100.x.x.x:4096`

Введите пароль, заданный на шаге 1, нажмите **«Подключить»** — и вы в деле.

## Как это работает

OpenCode Mobile — тонкий клиент. Он использует HTTP + SSE API opencode: список сессий, отправка сообщений, трансляция ответов и подписка на события изменения файлов. Все вызовы AI-моделей обрабатываются вашим сервером opencode — вы используете собственные API-ключи (OpenAI, Anthropic и т.д.), и приложение никогда их не касается. Приложение никогда не проксирует ваш код или разговор через наши серверы.

```
┌─────────────────────────────────────┐
│         OpenCode Mobile             │
│  (React Native / Expo)              │
└──────────────┬──────────────────────┘
               │  HTTP + SSE
               │  (локальная сеть / туннель)
               ▼
┌─────────────────────────────────────┐
│       Сервер opencode               │
│  (github.com/sst/opencode, MIT)     │
│  Запущен на вашем ПК / VPS          │
└──────────────┬──────────────────────┘
               │  Вызовы API
               ▼
┌─────────────────────────────────────┐
│   Ваш AI-провайдер                  │
│  (OpenAI / Anthropic / Gemini / …)  │
│  Ваши ключи, ваш счёт                │
└─────────────────────────────────────┘
```

## Как собрана эта сборка

Репозиторий **не хранит исходники приложения**. Он содержит только локализацию и патчи поверх оригинального проекта [`dzianisv/opencode-mobile`](https://github.com/dzianisv/opencode-mobile). Сборка происходит в GitHub Actions (`.github/workflows/sync-and-build.yml`):

1. скачивается релиз оригинального проекта;
2. в `src/lib/i18n/` кладётся `src/patches/ru.json` и добавляется локаль `ru`;
3. применяются патчи из `src/patches/` (см. ниже) — каждый из них падает со внятной ошибкой, если нужный файл в новом релизе изменился;
4. `npm install`, `npm run typecheck`, `npx expo prebuild`, сборка APK и публикация релиза.

Один и тот же патч не может «пройтись молча» по новой версии: при несовпадении маркеров шаг падает, и релиз не собирается — это лучше, чем тихо неработающая сборка.

### Что исправлено патчами

| Патч | Проблема | Что делает |
|---|---|---|
| `patch-settings.js` | Android-оверлей выбора языка молча режет кнопки до трёх, поэтому «Русский» (четвёртый) никогда не появлялся | Заменяет `Alert` на `Modal` со списком всех локалей |
| `patch-markdown.js` | В чате жирный текст (`**…**`) наезжал на соседние строки, межстрочный интервал был слишком тесным | Закрепляет единые метрики строки для всех вложенных `<Text>` (`BASE_TEXT` + `lineHeight` в теме), включает `includeFontPadding` для «й/ё» |
| `patch-keyboard.js` | Клавиатура закрывала панель ввода, тулбар и кнопку «Подключить» | Добавляет `src/lib/keyboard-inset.ts` (`useKeyboardInset`) и переводит чат и обе формы подключения на реальную высоту клавиатуры вместо `KeyboardAvoidingView`, который на Android не делает ничего |
| `patch-speech.js` | Голосовой ввод отвечал «Missing RECORD_AUDIO permissions.» и распознал только `en-US` | Убирает блокировку права в `app.json` (главная причина — см. ниже), локализует ошибки, добавляет кнопку «Открыть настройки», распознаёт на языке интерфейса, проверяет доступность распознавания; воркфлоу проверяет право в **собранном APK** |
| `patch-archive.js` | Не было ни архива сессий, ни выгрузки переписки | Экран «Активные / Архив», архив чата и массовый архив проекта, возврат из архива, выгрузка диалога в Markdown (поделиться / скопировать). Меню вынесены в `Modal`-лист (`ActionSheet`), потому что Android у `Alert.alert` оставляет максимум три кнопки |

Об ограничениях API архива стоит знать заранее: сервер opencode отдаёт архивные сессии только по запросу с `?archived=true` (по умолчанию они скрыты), а «разархивировать» через PATCH буквально нечем — обработчик пропускает `archived === undefined`, а `null` не проходит валидацию. Поэтому возврат шлёт `archived: 0`: сессия снова считается активной в приложении и в TUI, но в серверном списке по умолчанию (и в CLI) она останется скрыта.

#### v1 и v2 API opencode

Сервер отдаёт две поверхности одновременно: старую (`/session`, `/experimental/session`, `/global/event`) и новую (`/api/…`). Клиент определяет версию при подключении (`GET /api/info` против `GET /global/health` — по типу ответа, а не по коду: неизвестный маршрут на обеих версиях отдаёт веб-страницу с `200 text/html`) и хранит её в подключении.

Патчи одинаково применяются к обоим поколениям клиента, но работают по-разному:

| Что | v1 (`opencode ≤ 1.18.x`) | v2 (`/api/*`) |
|---|---|---|
| Список сессий для архива | `?archived=true` отключает серверный фильтр, ответ содержит обе стороны | фильтра нет вовсе — ответ и так содержит обе стороны, делим по `time.archived` у клиента |
| Запись архива | `PATCH /session/:id` с `time.archived` | **невозможна**: у `/api/session/:id` только `GET`, PATCH в таблице маршрутов нет |
| Клавиатура в чате | патч заменяет `KeyboardAvoidingView` на `View` с реальной высотой клавиатуры | патч не трогает экран: апстрим уже перешёл на `react-native-keyboard-controller` с `automaticOffset` |

Поэтому на v2 кнопки архива остаются видимыми, но нажатие честно сообщает, что сервер не умеет архивировать, — вместо того чтобы подтвердить диалог, который ничего не сделает. Выгрузка переписки работает на обеих версиях.

### Почему голосовой ввод не работал

В `app.json` оригинала у `expo-image-picker` стоит `"microphonePermission": false`. Плагин превращает это в `withBlockedPermissions([RECORD_AUDIO])` и пишет в манифест приложения

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" tools:node="remove"/>
```

Манифестный merger выполняет удаление безусловно, поэтому `withPermissions([RECORD_AUDIO])` от `expo-speech-recognition` теряется, и в релизном APK микрофона просто нет — модуль честно сообщает «Missing RECORD_AUDIO permissions.». Проверено на локально собранном 0.4.15: в merged-манифесте и в `aapt2 dump badging` права не было.

`patch-speech.js` задаёт image-picker настоящее описание микрофона (сам он его не запрашивает — только распознавание речи), блокировка исчезает, и право доходит до APK. Проверка в воркфлоу теперь смотрит на **собранный APK**, а не на наличие строки в манифесте: строка `tools:node="remove"` тоже содержит `android.permission.RECORD_AUDIO`, поэтому прежняя проверка проходила, пока право было вырезано.

### Диагностика бандла

Metro-минификатор экранирует весь не-ASCII как `\uXXXX`, а Hermes хранит строки в таблице как UTF-16LE. Поэтому поиск кириллицы по бандлу обычным `grep` всегда выдаёт «строк нет» — и это **не** признак того, что локализация не попала в сборку. Проверять надо так:

```bash
# JS-бандл (обычный текст)
grep -c 'u0420u0430u0441u0441u0443u0436' path/to/bundle.js
# Hermes-байткод (.hbc) — UTF-16LE
python3 -c "print(open('index.android.bundle','rb').read().count('Рассуждение'.encode('utf-16-le')))"
```

## Конфиденциальность и данные

- Приложение **не отправляет** ваш код, переписку или учётные данные ни на какой сторонний сервис. Всё общение идёт напрямую на ваш сервер opencode.
- **Аналитика и Sentry выключены по умолчанию** и включаются только после явного согласия в диалоге при первом запуске. Без `EXPO_PUBLIC_SENTRY_DSN` Sentry вообще не инициализируется (жёсткий no-op), а нативная загрузка Sentry-артефактов при сборке этого форка отключена.
- Учётные данные сервера хранятся локально в системном хранилище (Android Keystore) через `expo-secure-store`.
- **Выгрузка переписки** целиком локальная: диалог собирается на устройстве и передаётся либо в системное меню «Поделиться», либо в буфер обмена. Приложение ничего не отправляет само — учитывайте, кому вы передаёте текст дальше.
